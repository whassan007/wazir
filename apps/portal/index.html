Built for real systems

Three principles that separate Wazir from a conventional chat assistant.

Shell & AI Coexist

Deterministic classification routes ls, git, pipes, and SSH straight to your native PTY, while natural language routes to governed AI.

Local-First Fleet

Run Qwen models on Apple Silicon (MLX / Ollama) and Linux GPUs (DGX Spark) with lease-fenced worker dispatch.

Verified Execution

Completion requires observed test, build, or tool evidence—never an LLM's self-reported summary.

Your first five minutes

From installation to your first verified distributed task—while keeping your ordinary shell 100% functional offline.

1. Launch Wazir Shell

Open Wazir Shell from the macOS Dock, Linux launcher, or run wa shell.

2. Review Disclosures

Accept or decline minimal diagnostics. Declining never blocks your native shell.

3. Discover Local Model

Run wa doctor to discover local Ollama, MLX, or LM Studio endpoints.

4. Test a Native Command

Run git status -s or !ls -la directly in your persistent PTY.

5. Run an AI Task

Type ?explain the failing test and run vitest to route to local Qwen.

6. Open Mission Control

Launch Wazir Mission Control or run wa fleet to monitor jobs.

7. Inspect Verified Result

Inspect the 10-state execution graph and real test/build verification receipt.

8. Pair Another Machine

Register authorized macOS/Linux workers or pair GrapheneOS over scoped URI.

Privacy & diagnostics

Zero telemetry before acceptance. Declining diagnostic reporting disables event collection completely and never blocks your native shell.

When enabled, only allowlisted metadata (app version, OS/arch, error code, component ID, random installation ID) is collected. Raw shell histories, prompts, source files, API keys, tokens, and private paths are stripped and never collected by default.
