# Agent 26 Report — `assure` CLI (`fa/26-assure-cli`)

## Summary

Implemented the Wazir Formal Assurance CLI (`wa assure ...`) per `docs/formal-assurance/FORMAL_ASSURANCE.md` §2.8:
- `assure doctor` — probes the real host tools (`tools/z3-venv/bin/python3`, `tools/alloy/org.alloytools.alloy.dist.jar` + `tools/java/bin/java`, `tools/dafny/dafny`, `tools/scenic-venv`, `tools/verifai-venv`, `skills/formal/gam`) and reports installed status, exact versions, and which verdicts (`PROVED`, `BOUNDED_PASS`, `COUNTEREXAMPLE`, `FALSIFIED`, `NOT_FALSIFIED`, `NOT_RUN`) are achievable on this host.
- `assure spec add|list|show|approve` — manages versioned formal specification manifests with content hashing (`sha256:...`) and enforces that `approve` requires an explicit human reviewer (`--reviewer <human>`), rejecting missing, automated, or agent-driven approvals.
- `assure verify-ledger` — recomputes the hash-chained evidence ledger (`prevHash` → `entryHash` + monotonic fencing tokens) and fails closed on tampering.
- `assure run <component> [--property ID] [--tools ...]` — runs obligations (dynamically wiring into `./adapters` when merged, and honestly recording `NOT_RUN` otherwise; never fabricating passes), applies vacuity and trusted-base rules, and appends hash-chained ledger entries.
- `assure record <component>` — aggregates verdicts by weakest link, applies implementation refinement caps (`capImplementationVerdict`), evaluates the fail-closed release gate (`evaluateReleaseGate`), and prints/writes the machine-readable `AssuranceRecord`.
