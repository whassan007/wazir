1. **Spec Hash Algorithm Mismatch between Agent 11 (`registry.ts`) and Agent 28 (`specs/red_signal/compute_hash.py`)**:
   - Agent 11's `computeSpecHash(manifest)` in `packages/assurance/src/registry.ts` hashes the canonical JSON serialization of the `SpecManifest` object (with `content_hash` stripped).
   - Agent 28's `specs/red_signal/compute_hash.py` computes `content_hash` (`sha256:2979c3a117a8a6afff1bc7777294c1c6b9080744777fd0ba30034f89a38fab59`) by hashing the raw `manifest.yaml` text (with `content_hash: ""`) plus the SHA-256 digests of the referenced files (`red_signal.als`, `stopping_envelope.py`, `stop_command.dfy`, `red_signal_monitor.py`).
   - Additionally, `specs/red_signal/manifest.yaml` uses `commands: ["WitnessStop", "NoCrossOnRed"]` inside a block sequence item (`- tool: alloy`), which `parseYaml` in `registry.ts` parses into `SpecManifest`, and then `verifySpecHash(value)` in `parseSpecManifest()` compares `manifest.content_hash` against `computeSpecHash(manifest)` — which will throw `SpecificationReviewRequired('Spec hash mismatch')` when `new SpecRegistry('specs')` loads `specs/red_signal/manifest.yaml` unless `content_hash` in `specs/red_signal/manifest.yaml` (or `computeSpecHash` in `registry.ts`) is aligned.
2. **Z3 Adapter JSON Field Naming (`vacuity_probe` vs `vacuityProbe`) for Python Obligation Scripts**:
