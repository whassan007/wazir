# Agent 13 — Hash-chained evidence ledger

Implemented `packages/assurance/src/ledger.ts` and tests in `packages/assurance/src/__tests__/ledger.test.ts`. No shared files or package index were edited.

The ledger extends the C0 LedgerEntry locally with required specVersion and fencingToken, plus optional seed and leaseToken. Entries use deterministic recursive JSON key sorting and SHA-256, zero-based indices, and a 64-zero genesis hash. Memory and JSON file stores return detached snapshots. File writes reload state under an exclusive lock and atomically rename the replacement JSON file. Historical evidence is never removed by the API.

Lease fencing rejects invalid/lower tokens and same-epoch superseded workspace revisions. `setLeaseFence(token, workspaceRev)` publishes a replacement worker's fence before evidence arrives. The synchronous `LeaseFenceValidator` callback can consult authoritative lease state and reject a superseded revision even when a worker presents a higher token. `invalidatePriorEvidence(newCommit)` persists the eligible commit, rejects old-commit writes, and hides old evidence from commit queries while preserving the audit chain. Without explicit invalidation, queries filter by source commit.

`verifyLedger(entries, checkpoint?)` and the instance method recompute content hashes, sequence indices, and links and throw LedgerIntegrityError at the first mismatch. Persist `ledger.checkpoint` in a trusted external location to detect suffix truncation, including deletion of all entries. A hash chain alone cannot distinguish a valid prefix from intentional tail deletion, nor detect wholesale rewriting with recomputed hashes; the trusted checkpoint supplies that boundary.

Tests cover valid chains, defensive snapshots, tampered verdict/witness/specHash/prevHash, invalid hashes, reordering, interior deletion, checkpoint truncation, stale tokens and revisions, authoritative callback rejection, commit invalidation, persistence across independent instances, corrupted file rejection, competing writer locks, and canonical JSON validation.

Integration/limits: consumers must import the ledger module directly until the integration owner exports it. The CLI wrapper is outside this agent's owned paths. File locking is single-host, fail-fast, and requires every writer to follow the protocol; a process crash can leave a lock requiring operator removal. No distributed transaction with the existing lease store is claimed: callers must serialize authoritative lease changes with writes through their existing fencing path, or provide the validator under an appropriate external transaction. Fence/active-commit store metadata is trusted control state, not part of the evidence hash chain. Atomic rename prevents partial JSON replacement but does not promise power-loss durability via fsync.
