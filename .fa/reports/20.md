# Agent 20 — GAM adapter

Branch: `fa/20-gam-adapter`

## Delivered

- `packages/assurance/src/adapters/gam.ts`
  - `parseGalJson` / `GalParseError`: reads `{law, enterprise}` (also accepts `lawModel`/`enterpriseModel`, `phiL`/`phiE`). Checks the shape and requires every policy to have a polarity (`modality` / `allow_deny` / `deontic_status`). A missing polarity is a parse error, not a default.
  - `GamModel`: one vocabulary (Φ_L ∪ Φ_E, with origin kept only for provenance) and a polarity split RA±, RU±, UP±, RP±, D±. Edge directions follow the GAM `_ingest` table: `Acts` is Role→User, `CanAssignTo` is Activity→Role, `CanAct` is User→Role. Unknown relation and policy types are ignored, as in GAM.
  - `ConsistencyChecker` (`Con`): ACTIVITY_CONFLICT, ROLE_OCCUPANCY_CONFLICT, PROCESS_ACCESS_CONFLICT (UP⁻ and RP⁻), SEPARATION_VIOLATION, DELEGATION_CONFLICT and DELEGATION_LAUNDERS_PROHIBITION. Each is computed over closures (RR*, PP*, Reaches, delegation), and every violation carries `grantedVia` / `prohibitedVia` / `reachedVia` derivation paths.
  - `OntologyChecker`: `{process, activity}`, `{parentRole, childRole}` and `{parentProcess, childProcess}` at any depth (ONTOLOGY_GAP), plus `precedence` / `forbidden-precedence` over Next⁺ (SCENARIO_VIOLATION).
  - `emitAlloyTwin(galJson, {moduleName, scope})`: a self-contained, deterministic Alloy 6 module with sorts, `one sig Phi` fields, a `Facts` fact, `WellFormed`, `roles`/`procs`/`effAct`, `pred Con`, `check Consistent`, and one `check` per ontology or scenario requirement. D± is only checked by the built-in engine, and the generated file says so in a comment.
  - `GamAdapter` (`tool = 'gam'`):
    - Gets the artifact from `obligation.artifactPath` (resolved against `workspaceDir`) or from inline `metadata.galJson`.
    - Uses an external CLI if one is configured (`cliPath` or `$GAM_CLI`; called as `<cli> check --json <artifact>`, the runner can be injected). Otherwise it runs the built-in engine.
    - With `requireCli`, a missing or unavailable CLI gives NOT_RUN. Without it, the adapter falls back to the built-in engine.
- `packages/assurance/src/__tests__/gam-adapter.test.ts`: 17 tests.

## Verdict mapping

| Condition | Verdict |
|---|---|
| no artifact path / unreadable file / CLI required but absent | `NOT_RUN` |
| invalid JSON, missing Φ_L or Φ_E, bad shape, policy without polarity, CLI non-JSON output | `ERROR` |
| Φ_L empty; Φ_L fails `Con` alone; Φ_L role-level ± clash over closure; cyclic PP/RR in Φ_L | `INCONSISTENT_ASSUMPTIONS` |
| any `Con` or ontology/scenario violation | `COUNTEREXAMPLE`, witness `{consistencyViolations, ontologyViolations}` |
| `consistent && satisfied` + vacuity probe passes | `BOUNDED_PASS` |
| `consistent && satisfied` but vacuity probe fails (Φ_L/Φ_E not inhabited, no user in RU⁺ and no structural requirements, cyclic hierarchy) | `INCONSISTENT_ASSUMPTIONS` (via `applyVacuityProbe`) |
| CLI reports `consistent` but no ontology result | `UNKNOWN` (`ontology_not_checked`, because `Con` passing ≠ compliant) |
| CLI timeout | `UNKNOWN` |

The raw verdict comes from the shared `mapNativeOutcomeToVerdict({tool:'gam', consistent, satisfied})` in `verdict.ts`, so the GAM mapping is defined in one place.

## Limits / follow-ups

- The Appendix B fixtures are rebuilt from the `SKILLS_INSTALL.md` table. They are not imported from GAM's `src/data/agent-intrusion.js` because that repo isn't in this workspace. The principals `WorkerPod`, `ConnectorSvc` and `CIRunner` were added so that every identity `Acts` for some user, as the GAM pitfalls require.
- The emitted `.als` twin is only checked as text. No Alloy Analyzer is installed here, so it hasn't been run in Alloy. A test that runs it end-to-end belongs with the Alloy adapter or CI.
- Defeasibility (Lex*), `minimalConflict` (MUS) and the SAT cross-check (`ENGINE_DISAGREEMENT`) are not reimplemented. Use the external GAM CLI for those.
- The CLI output contract is assumed to be `{consistency:{consistent,violations}, ontology:{satisfied,violations}}` (the `/api/models/validate` shape) or a flat `{consistent, satisfied, violations, ontologyViolations}`. Override `cliArgs` if the real CLI takes different arguments.
- `index.ts` was not edited (it isn't an owned path). Whoever owns `index.ts` needs to add `export * from './adapters/gam'`.
