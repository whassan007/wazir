# Agent 25 — Refinement map and implementation capping

Implemented on `fa/25-refinement-map` within the assigned paths. `packages/assurance/src/index.ts` was not edited.

## Changes

- `parseRefinementMap(source)` validates JSON and the documented flat YAML mapping/list schema against `RefinementMap`. Invalid shapes, unknown production modes, duplicate YAML keys, and unsupported YAML constructs fail explicitly.
- `evaluateRefinementLink(entry, modelResult, options)` reports model and implementation verdicts separately. A compiled Dafny link requires an existing production file, equal nonempty source/workspace revisions, a matching pinned compiler version, Dafny proof, and explicitly empty trusted-base gaps.
- A refinement-proof link requires a proved proof result with explicitly empty trusted-base gaps and metadata binding it to the current revision, plus matching source/workspace revisions and an existing production file.
- Contract tests, absent links, runtime hand-translation values, missing files, stale revisions, missing proofs, and compiler gaps cap implementation claims at `NOT_VERIFIED`. Contract-test recording survives both capping and model failure.
- Model failures (`COUNTEREXAMPLE`, `FALSIFIED`, `INCONSISTENT_ASSUMPTIONS`, `ERROR`, `UNKNOWN`, `NOT_RUN`) propagate unchanged, even when the production link is absent.

## API and limits

Options provide `sourceCommit`, `workspaceRev`, `workspaceDir`, `compilerVersion`, `pinnedCompilerVersion`, `refinementProof`, and `contractTestsRecorded`. Verification results can bind their revision using `metadata.workspaceRev`; a conflicting model revision is rejected, and refinement proofs require that metadata explicitly.

The dependency-free YAML parser intentionally implements the documented flat schema rather than general YAML (no anchors, multiline scalars, or flow-style YAML). JSON supports the full schema including empty mapping lists. Production paths must identify concrete files; wildcard paths conservatively cap until resolved by the caller. Provenance inputs are caller-supplied evidence; this layer does not invoke a compiler or independently establish artifact identity.
