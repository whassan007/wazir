# Checkpoint 0001

## Objective
Design P0-A (scoped verification) and P0-B (task classification fast path).

## Evidence
`packages/tools/src/process-tools.ts` `makeCheckTool()`: build/test/lint/typecheck tools run
`npm run <script>` at `ctx.projectRoot` (repo root) with NO workspace scoping; `script` input only
selects a *different* npm script name, not a workspace. `packages/agents/src/codingAgent.ts` VERIFY
phase calls `runtime.executeTool(check, {})` — always the unscoped root script.
Workspace layout: `package.json` workspaces = `packages/*`, `packages/runtimes/*`, `apps/*`; each has
its own `build`/`test`/`typecheck` scripts (confirmed for `@wazir/agents`, `@wazir/core`, `@wazir/cli` —
all `tsc --build`). `@wazir/desktop` (Tauri) is the one dragging in `crates.io` network access.
`codingAgent.ts` only reads `request.taskType` in one place (`groundedResearch`); no fast path exists
for 'chat'/'generation'/'analysis' task types — PLAN always runs regardless of type.

## Decision
P0-A: add a `workspaces?: string[]` input to `makeCheckTool`, appended as `--workspace=<name>
--if-present` flags to the npm invocation. In codingAgent.ts's VERIFY loop, resolve `filesChangedSet`
to the workspace package(s) actually touched; if all changed files fall inside exactly-identifiable
workspaces (none outside any workspace dir), run checks scoped to those workspaces and record a
justification message; otherwise (changes at repo root, or no scoping possible) fall back to the full
unscoped run (safe default — never silently narrow verification we can't justify). Report every skip
decision as a `message` turn.
P0-B: add a lightweight single-inference fast path in `codingAgent.run()` gated on
`request.taskType` being `'chat'`/`'generation'`/`'analysis'` — one `generate()` call, parse for
`{"action":"done",...}`, skip PLAN and the VERIFY check battery entirely (mutationRequired forced
false for these contract types). Conservative default in `apps/cli/src/run.ts`'s `planTask`: only
engage this when `--type` is explicitly one of these three; do not auto-guess from prompt text (avoids
misclassifying a task that actually needs mutation — safer given time budget).

## Expected impact
P0-A: G04/G05/G06-style tasks (write one file) stop triggering the Tauri desktop build; verification
scoped to the actually-relevant package, still fails loudly if that package's own checks fail.
P0-B: an explicit `--type chat` run skips PLAN+VERIFY overhead entirely (single round trip).

## Timeout
This design pass: done. Implementation: budgeting ~15 min for P0-A, ~10 min for P0-B, remainder for
rebuild + benchmark + report within the 40-minute session.

## Success condition
Live `wa run` of a single-file Python change no longer invokes `npm run build`/`test` at the repo root;
`@wazir/desktop` not touched; task still correctly fails if the scoped check fails.

## Recovery procedure
If scoping introduces a false-pass (a real failure in an untouched-but-affected package goes unnoticed),
revert to full-repo scope — the fallback path (changes outside any workspace, or any ambiguity) already
defaults to full scope, so the blast radius of a scoping mistake is bounded to same-workspace-only changes.
