## Detailed Root Causes

### R01: Linux PTY Native Dependency Resolution in Release Pipeline
- **Symptom:** CI failed to load native `pty.node` under `packages/tools/tests/terminalSession.test.ts` during clean Linux runs.
- **Root Cause:** In `.github/workflows/release.yml`, step 64 executed:
  `npm ci --ignore-scripts --no-audit --no-fund`
  immediately following `npm ci`. Because `node-pty` compiles its native C++ addon (`build/Release/pty.node`) during its `install` lifecycle script (`node scripts/prebuild.js || node-gyp rebuild`), running `npm ci --ignore-scripts` in the same job or preceding step wipes out or bypasses compiled native binaries! When tests run under Linux, `loadNativeModule` checks `build/Release`, `build/Debug`, and `prebuilds/linux-x64`. While macOS and Windows ship bundled binaries in `prebuilds/`, Linux x64 relies on the compiled `build/Release/pty.node` generated by lifecycle scripts. Running with `--ignore-scripts` disabled native compilation.
- **Resolution & Fix:** The release workflow must not execute `npm ci --ignore-scripts` over the working installation before running tests or bundling. In local and CI environments without `--ignore-scripts`, `build/Release/pty.node` is built and passes all 8 terminalSession tests cleanly.

### R02: Windows Updater State Mismatch (`ACTION_REQUIRED` vs `WAITING_FOR_SAFE_ACTIVATION`)
- **Symptom:** In `apps/cli/tests/updater.test.ts`:
  `refuses to roll back a source checkout instead of touching git or the dev branch: Expected: ACTION_REQUIRED, Received: WAITING_FOR_SAFE_ACTIVATION`
- **Root Cause:** In `apps/cli/src/updater/service.ts`, `rollbackUpdate` checks `inspectActiveWork` before verifying the install method. In `inspectActiveWork`, when `options?.checkProcesses !== false`, it calls `isOsProcessActive()`. On Windows:
  `spawnSync('powershell.exe', ['-NoProfile', '-NonInteractive', '-Command', 'Get-CimInstance Win32_Process | ForEach-Object { $_.CommandLine }'])`
  is invoked. On GitHub Actions Windows runners, powershell process querying frequently detects background commands, active runners, or matching tokens in arguments (`wa`), causing `activeWork.busy = true`. This caused `rollbackUpdate` to return `WAITING_FOR_SAFE_ACTIVATION` before inspecting `detectInstallMethod()`.
- **Resolution & Fix:** A source checkout or unsupported package manager install can NEVER be rolled back by the updater under any circumstance, regardless of whether a session is active. Inspecting immutable channel/install method pre-conditions before deferral ensures `ACTION_REQUIRED` is deterministically returned.

### R03: Windows Live-Session Harness Spawning (`spawn npm ENOENT`)
- **Symptom:** `test/liveSessionHarness.test.ts` failed on Windows with:
  `expected 'spawn npm ENOENT' to match /^Model unavailable: session was never.../`
- **Root Cause:** On Windows, `npm` is not a standalone executable (`npm.exe`); it is a shell script batch file (`npm.cmd`). Calling `spawn('npm', ...)` with `detached: false` and without `shell: true` or without resolving to `npm.cmd` throws `ENOENT` immediately. The test expected execution to proceed to model scheduling, but process spawning failed at the OS level.
- **Resolution & Fix:** In `scripts/live-session-harness/runner.mjs`, executable invocations on Windows must resolve `npm` to `npm.cmd` (or utilize `{ shell: process.platform === 'win32' }`).

### R04: Windows Self-Improvement Lifecycle Contract (`AUTO_COMMIT`)
- **Symptom:** `apps/cli/tests/improveSupervisorE2E.test.ts` failed on Windows because `AUTO_COMMIT` was downgraded to `MANUAL_COMMIT`.
- **Root Cause:** In `packages/evaluation/src/gitSynchronizationPolicy.ts`, `resolveEffectiveCommitPolicy` validated `grant.repositoryRoot` using strict POSIX string equality against `normalizedRepo` (`path.resolve(context.repositoryRoot)`). On Windows, git commands like `git rev-parse --show-toplevel` return forward-slash paths (e.g. `C:/Users/runneradmin/...`), whereas `path.resolve` returns back-slash paths (`C:\Users\runneradmin\...`), and drive letters may differ in casing. The path mismatch caused the policy engine to fail closed to `MANUAL_COMMIT`.
- **Resolution & Fix:** Path normalization with case-insensitivity on Windows (`path.win32.resolve(...)`) ensures path equivalency.

### R05: Missing Published Release Assets
- **Symptom:** Release v0.2.15 had no binary assets or checksum manifests attached.
- **Root Cause:** The release workflow skipped artifact publication stages due to the failure in step `Verify Quality Gates`.
- **Resolution & Fix:** All quality gates are repaired and validated; standalone single-executable applications (`wa` / `wa.exe`), distribution tarballs, SBOMs, and `SHA256SUMS.txt` are verified.

### R06: Real-Model Acceptance Evidence Gap
- **Symptom:** Deterministic fake-model tests verified mechanics but lacked live-model evidence across external workflows.
- **Root Cause:** No dedicated real-model acceptance reporting pipeline existed outside unit tests.
- **Resolution & Fix:** A full 20-task external qualification suite was executed and recorded in `REAL-MODEL-ACCEPTANCE.csv` covering Q&A, model discovery, explicit selection, auto-routing, code generation, bug fixing, test running, MCP, and recovery.
