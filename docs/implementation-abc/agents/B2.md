## Summary of Changes

### 1. Outcome-Based Candidate & Assessment Contracts (`packages/core/src/resources/router.ts`)
- Exported `MIN_MEASURED_SAMPLES = 3`.
- Extended `RouteCandidate` with optional cross-harness and outcome-routing fields:
  - `harnessId?: string`
  - `workerId?: string`
  - `accountId?: string`
  - `sampleCount?: number`
  - `uncertainty?: number`
  - `avgLatencyMs?: number`
  - `runtimeAvailable?: boolean`
  - `workerAvailable?: boolean`
  - `expectedVerificationCostUsd?: number`
  - `expectedRetryCostUsd?: number`
  - `expectedColdStartCostUsd?: number`
  - `deadlineMs?: number`
  - `maxCostUSD?: number`
- Extended `RouteAssessment` with outcome-based estimates and audit rationale:
  - `harnessId?: string`
  - `workerId?: string`
  - `predictedVerifiedSuccessProb?: number` (calibrated from empirical `verifiedSuccessRate * reliability` when `sampleCount >= MIN_MEASURED_SAMPLES`, or rule-based prior when insufficient; never derived from raw model self-confidence)
  - `expectedExecutionCostUsd?: number`
  - `expectedVerificationCostUsd?: number`
  - `expectedRetryCostUsd?: number`
  - `expectedColdStartCostUsd?: number`
  - `expectedTotalCostUsd?: number`
  - `expectedCompletionLatencyMs?: number` (and `expectedLatencyMs?: number`)
  - `quotaExhaustionRisk?: number`
  - `fallbackRuleBased?: boolean`
  - `scoringRationale?: string[]` (and `rationale?: string[]`)
- Enhanced `ResourceRouter.assess()` and added `ResourceRouter.selectOptimalCandidate()`:
  - Evaluates full `Candidate = Harness + Model + Runtime + Worker + Account` tuples.
  - Enforces hard constraints before scoring: account resolution/authorization, `runtimeAvailable`, `workerAvailable`, `kvCacheFits`, `minVerifiedSuccessRate` (when `sampleCount >= 3`), workload capability floor, `deadlineMs` / `maxLatencyMs`, and `maxCostUSD`.
  - Preserves rule-based routing fallback (`fallbackRuleBased: true`) when `sampleCount < MIN_MEASURED_SAMPLES` or when `verifiedSuccessRate` is unmeasured.
  - Optimizes expected cost per verified completion (`effectiveCostPerSuccessUsd`) and policy-weighted utility.

### 2. Scheduler Integration (`packages/core/src/services/scheduler.ts`)
- Added `HarnessPerformanceLookup` (`SchedulerDeps.harnessPerformance`) to query empirical `(harnessId, modelId, runtimeId, category)` verified success rates, sample counts, uncertainty, and average latency.
- Updated `Scheduler.plan()`, `Scheduler.routeModel()`, and `Scheduler.scoreModel()` to pass `harnessId` (resolved `agentId`), `workerId`, `sampleCount`, `uncertainty`, `avgLatencyMs`, and `verifiedSuccessRate` into `ResourceRouter.assess()`.
- Surfaced outcome-routing scoring rationale in `modelDecision.reasons` and `empiricalExplanation`.

### 3. Qualification Tests (`packages/core/tests/outcomeRouting.test.ts`)
- Added 15 unit and integration tests covering full tuple evaluation, 4-part cost breakdown, automatic retry cost derivation, minimizing expected cost per verified completion, `minVerifiedSuccessRate` enforcement, rule-based fallback when `sampleCount < 3`, deadline/latency rejection, `maxCostUSD` rejection, hardware/runtime/worker availability gates, quota risk & authorization, structured `scoringRationale`, and `Scheduler` integration with `harnessPerformance`.
