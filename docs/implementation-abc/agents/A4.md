# Agent A4: Harness Selection and Dispatch (`feat/harness-dispatch`)

## Summary of Implementation

Implemented `HarnessDispatchService` in `packages/core/src/services/harnessDispatchService.ts` and comprehensive unit & integration tests in `packages/core/tests/harnessDispatch.test.ts`.

### Key Capabilities Delivered

1. **`HarnessRunner` & `HarnessDispatchService` Registration:**
   - Defined `HarnessRunner` (`descriptor`, optional `isAvailable`, `execute(request: UnifiedExecutionRequest)`).
   - Implemented `registerHarness`, `getHarness`, and deterministic `listHarnesses` (ordering native harnesses first, then lexicographically by `harnessId`).

2. **Capability Matching & Explicit Harness Pinning (`resolveHarness`):**
   - Evaluates task-level policy via `PolicyEngine.evaluateTask` prior to dispatch.
   - Matches `supportedTaskTypes` and required `HarnessCapability` items (including automatic `checkpoint-resume` capability requirement when `checkpointId` or `resumeContext` is present).
   - Honors explicit `request.harnessPreference` pins: fails closed with `HarnessResolutionError` when the pinned harness is unregistered, unavailable, or lacks required capabilities unless `request.constraints.allowFallback === true` and `strictPin` is not set.
   - Enforces `provider_only` routing constraints (`Scheduler` routing config or `policyContext.routingMode`): rejects external harnesses that manage their own model selection (`allowsModelSelection: false`) and prevents pinning non-matching provider models.

3. **Dispatch, Controlled Fallback, Timeout & Cooperative Cancellation (`dispatch`):**
   - Enforces wall-clock timeout (`request.constraints.maxDurationMs` -> `MAX_WALL_CLOCK`) and cooperative cancellation (`request.isCancelled` -> `CANCELLED`).
   - Supports controlled fallback to the next eligible harness when the primary harness fails with an infrastructure error (`errorKind === 'infrastructure'`) or `'unknown'`/`'interrupted'` status and `allowFallback === true`.
   - Preserves `executionId`, `taskId`, and decrements remaining budgets (`maxTokens`, `maxToolCalls`, `maxCostUSD`, `maxDurationMs`) while passing accumulated consumption via `resumeContext`.
   - Enforces **Invariant 2 (Tool Dispatch vs. Confirmed Side Effects)**: blocks automatic fallback (`UNCONFIRMED_SIDE_EFFECT_BLOCKS_FALLBACK`) if any mutating tool call has `TOOL_OUTCOME_UNKNOWN` or `STARTED` state in `ExecutionEngine` or the harness result, or if files were mutated prior to an interrupted/unknown termination.
   - Enforces **Invariant 3 (Monetary Cost Semantics)**: preserves `costStatus: 'UNKNOWN'` with `costUSD: undefined` and never coerces unknown costs to `0`.

4. **Independent Controller Verification Pipeline:**
   - Enforces **Invariant 1 (Physical Execution Facts vs. Model Claims)**: every harness result starts with `verified: false` until controller verification (`verifyExecution` callback or `VerificationEngine` oracle runs + `verifyCompletion`) confirms physical workspace state, protected-path integrity, required mutations, and passing checks.
   - Records durable execution state, tool calls, file mutations, checks, verification evidence, token usage, evaluation, and terminal status on `ExecutionEngine`.
