# Agent C4 — Remote Checkpoint Transport (`feat/checkpoint-transport`)

## Overview
Implemented authenticated, content-addressed, resumable remote checkpoint transport across the control plane and distributed workers without mutating shared barrel files (`index.ts` or `server.ts`).

## Owned Files Created
1. `packages/core/src/services/checkpointTransportService.ts`
   - `CheckpointTransportService` for splitting `ExecutionCheckpoint` snapshots into content-addressed SHA-256 blobs (`computeBlobHash`) and HMAC-SHA256 signed/authenticated manifests (`CheckpointTransferManifest`).
   - Deterministic `computeSnapshotDigest` matching `CheckpointService.computeDigest` (`sha256` over sorted `[relativePath, content]` pairs + `rev:${workspaceRevision}\n`).
   - Credential & secret scrubbing (`scrubCheckpointSecrets`): scans `description`, `metadata`, `contextSnapshot.metadata`, and `planState.metadata` for `API_KEY`, `SECRET`, `TOKEN`, `PASSWORD`, `PRIVATE_KEY`, PEM private key blocks, and `Bearer` tokens, supporting both `redact` (default) and `reject` policies.
   - Resumable/deduplicated blob storage (`registerManifest`, `missingBlobs`, `putBlob`, `commitCheckpoint`, `getBundle`, `reconstructCheckpoint`, `restoreOnTarget`).
   - Size & retention limits (`maxCheckpointBytes` default 50 MB, `maxFileBytes` default 10 MB, `maxStoredCheckpoints` default 100, and TTL-based `pruneExpired()` with unreferenced blob garbage collection).
   - Stale checkpoint restoration protection (`validateTargetRestoration`): rejects restoring a checkpoint onto an execution with a newer confirmed `workspaceRevision` unless `allowRollback: true` is explicitly passed.
   - Source and destination worker identity preservation & enforcement (`sourceWorkerId`, `targetWorkerId`, `downloadedByWorkerId`, `restoredByWorkerId`).

2. `apps/api/src/checkpointTransportRoutes.ts`
   - `registerCheckpointTransportRoutes(app, transportService, authMiddleware?)` registering:
     - `POST /api/v1/checkpoints/manifests`
     - `PUT /api/v1/checkpoints/blobs/:hash`
     - `POST /api/v1/checkpoints/:checkpointId/commit`
     - `GET /api/v1/checkpoints/:checkpointId/bundle`

3. `packages/workers/src/checkpointTransportClient.ts`
   - `CheckpointTransportClient` for pushing checkpoints from source workers (`pushCheckpoint` with chunked missing-blob upload and bounded exponential backoff retry on transient interruptions) and pulling/validating/materializing checkpoints onto target workers (`pullBundle`, `pullAndMaterialize` via `CheckpointService.materializeOnTarget`).

4. `packages/core/tests/checkpointTransport.test.ts`
   - 14 unit and HTTP integration tests covering end-to-end Worker A -> Control Plane -> Worker B transfer, content-addressed blob deduplication, network interruption & resumable retry, tampered blob/digest rejection, unauthenticated transfer & forged HMAC rejection, secret redaction & rejection, file/checkpoint size limits, checkpoint retention & TTL pruning, stale revision protection, worker identity validation, and unsafe path traversal rejection.
