## Summary of Changes

1. **Durable Operation Identity & Idempotency Ledger (`OperationReconciliationGuard`)**:
   - Added `computeOperationKey` (`sha256(executionId + callId + toolName + argumentsHash + workspaceRevision)`) and `computeSemanticOperationKey` (`sha256(executionId + toolName + argumentsHash + workspaceRevision)`).
   - Added `classifyToolOutcome` classifying checkpoints/outcomes into `CONFIRMED_COMPLETED`, `CONFIRMED_FAILED`, and `OUTCOME_UNKNOWN`.
   - Implemented `OperationReconciliationGuard` (`fromExecutionRecord`, `recordConfirmedMutation`, `checkDuplicateOperation`, `listReceipts`) to block duplicate side-effect execution across retries or cross-harness handoffs when a tool call with the same `callId` or `(toolName, argumentsHash, workspaceRevision)` has already been confirmed or reconciled as `APPLIED`.

2. **Lease & Ownership Fencing (`verifyLeaseFencing`)**:
   - Added `verifyLeaseFencing`, `LeaseFencingState`, `LeaseFencingClaim`, and `LeaseFencingResult` (`code: 'STALE_WORKER_FENCED'`).
   - Extended `RecoveryManager` with `reassignExecutionLease` and `verifyWorkerReport` to increment lease fencing epochs on worker reassignment and reject late completions/events from superseded or expired workers.

3. **Side-Effect Reconciliation Before Cross-Harness Resume (`reconcileBeforeCrossHarnessResume`)**:
   - Inspects physical workspace state for any `STARTED` or `OUTCOME_UNKNOWN` tool calls.
   - Marks `APPLIED` calls completed without re-running them, records their receipt in `OperationReconciliationGuard`, and advances workspace revision when appropriate.
   - Marks `NOT_APPLIED` (and `READ_ONLY`) calls safely retryable.
   - Blocks `UNDETERMINED` outcomes fail-closed (`BLOCKED_UNDETERMINED_OUTCOME`) unless explicit `operatorAuthorizedResolution` (`assume_applied`, `allow_retry`, or `abort`) is provided.
