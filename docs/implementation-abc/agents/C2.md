# Agent C2 — Cross-Harness Handoff and Resume (`feat/harness-resume`)

## Overview
Implemented portable cross-harness handoff generation, verification, and semantic execution resumption across compatible harnesses (`native`, `acp`, `claude-code`, `codex`, `gemini-cli`, `external-cli`) and workers.

- `packages/core/src/services/handoffService.ts`
- `packages/core/src/services/harnessResumeService.ts`
- `packages/core/tests/harnessResume.test.ts`
- `docs/implementation-abc/agents/C2.md`

## Key Capabilities & Invariants Enforced

1. **Portable Handoff Creation & Verification (`HandoffService`)**
   - Preserves 100% backward compatibility with all existing `HandoffService` APIs (`create`, `createAutomatic`, `list`, `get`, `remove`, `resume`, `toMarkdown`).
   - Added `createPortableHandoff(executionId, options)` producing a schema-versioned (`PORTABLE_HANDOFF_SCHEMA_VERSION = 1`) `PortableHandoff` record from durable controller facts (confirmed tool calls, file mutations, passing verification checks at current revision, unresolved tool checkpoints, consumed/remaining budgets, and policy context).
   - Added `verifyPortableHandoff(handoff)` verifying `schemaVersion === 1`, required fields, credential redaction, and canonical SHA-256 `integrityDigest`.

2. **Semantic Continuation Without Raw Transcript Replay (`HarnessResumeService.buildContinuationPrompt`)**
   - Generates a structured continuation objective from confirmed durable facts (completed actions, modified files, passing verification evidence at current revision, reconciled side effects, remaining pending subtasks, and remaining budgets).
   - Explicitly omits raw model transcripts (`generation.token`, unparsed `agent.turn` prose) and makes no assumption of KV-cache portability across harness architectures.

3. **Target Harness Capability & Compatibility Resolution (`HarnessResumeService.resolveTargetHarness`)**
   - Resolves target harness descriptors (`native`, `acp`, `claude-code`, `codex`, `gemini-cli`, `external-cli`, plus custom registered harnesses) and verifies `supportedTaskTypes`, required `HarnessCapability` flags (defaulting to `['checkpoint-resume']`), external binary availability (`requiresBinary`), and permission mode constraints.

4. **Budget Carry-Forward & Exhaustion Refusal (`HarnessResumeService.computeRemainingBudget`)**
   - Carries forward `remainingBudget = maxBudget - consumedBudget` across `maxTokens`, `maxToolCalls`, `maxModelCalls`, `maxCostUSD`, and `maxDurationMs`.
   - Refuses resumption (`status: 'rejected'`, `failureCode: 'BUDGET_EXHAUSTED'`) if any budget dimension is exhausted (`<= 0`).

5. **Policy Non-Escalation Enforcement (`HarnessResumeService.validatePolicyNonEscalation`)**
   - Prevents authorization escalation across handoffs by verifying that target policies, harnesses, and runtimes cannot weaken:
     - `localOnly` (`true` -> `false` or routing to hosted runtimes/harnesses)
     - `dataClassification` (downgrading sensitivity rank `restricted > sensitive > internal > public`)
     - `allowHostedProviders` (enabling when disabled on source policy or when `localOnly` / `sensitive` / `restricted` applies)
     - `allowedTools` (adding tools outside the source whitelist)
     - `protectedPaths` (dropping any protected path from the source policy)

6. **Workspace Drift Detection & Evidence Revalidation (`HarnessResumeService.revalidateWorkspace`)**
   - Compares current workspace revision and physical SHA-256 content digest against `handoff.workspaceRevision` and `handoff.workspaceContentDigest`.
   - When the workspace drifts outside the checkpoint (either via revision increment or physical file modification on disk), invalidates prior verification evidence (`evidenceInvalidated: true`, `validVerificationEvidenceIds: []`, `staleVerificationEvidenceIds: [...]`) and requires fresh `build` and `test` verification before completion.

7. **Unresolved Mutating Side-Effect Blocking**
   - Blocks resumption (`status: 'blocked'`, `failureCode: 'UNRESOLVED_SIDE_EFFECTS'`) whenever `handoff.unresolvedSideEffects` contains any unreconciled non-`READ_ONLY` tool call (`STARTED` or `OUTCOME_UNKNOWN`).
   - Allows interrupted `READ_ONLY` tool calls to proceed and unblocks mutating calls once reconciled via `ExecutionEngine.reconcileToolCall` or `reconciledCallIds`.
