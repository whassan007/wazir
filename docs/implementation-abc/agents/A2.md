# Agent A2 — Native Execution Adapter (`packages/agents/src/nativeHarnessAdapter.ts`)

## Overview

Agent A2 implements the Wazir Native Execution Harness Adapter (`NativeHarnessAdapter`) on branch `feat/native-harness-adapter`, wrapping Wazir-native `AgentAdapter` implementations (`CodingAgent`, `ChatAgent`, `StepAgent`, or custom adapters) behind the shared Cross-Harness Execution Contract (`UnifiedExecutionRequest` -> `UnifiedExecutionResult`, plus `HarnessDescriptor`).

## Key Responsibilities & Semantic Invariants Implemented

1. **Zero-Duplication Native Agent Wrapping:**
   - `NativeHarnessAdapter` wraps any native `AgentAdapter` (`CodingAgent` by default, or `ChatAgent` / `StepAgent` via factory helpers `createNativeCodingHarnessAdapter`, `createNativeChatHarnessAdapter`, `createNativeStepHarnessAdapter`) without duplicating its internal turn loop.
   - Intercepts `AgentRuntime.generate`, `AgentRuntime.executeTool`, and `AgentRuntime.escalate` to record telemetry, tool call checkpoints, model route switches, and physical workspace mutations.

2. **Invariant 1 — Physical Execution Facts vs. Model Claims (`verified` vs. `status: 'completed'`):**
   - When the wrapped agent yields `{ kind: 'done' }` (even if `CodingAgent` internally sets `terminationReason: 'VERIFICATION_PASSED'`), `NativeHarnessAdapter` treats the result as an *apparent* completion (`status: 'completed'`, `verified: false`, `terminationReason: 'COMPLETED'`) unless independent controller verification evidence is bound at the final `workspaceRevision` (via `verifyOutcome` hook or explicit `verificationEvidenceIds`).
   - If `verifyOutcome` returns `verified: false`, the execution transitions to `status: 'failed'`, `verified: false`, `terminationReason: 'VERIFICATION_FAILED'`, `errorKind: 'verification'`.

3. **Invariant 2 — Tool Dispatch vs. Confirmed Side Effects (`ToolCallCheckpoint` & `ToolCallRecord`):**
   - Every tool invocation records a `ToolCallCheckpoint` (`STARTED` -> `COMPLETED`, `FAILED`, or `OUTCOME_UNKNOWN`) with its `ToolSideEffectClass` (`READ_ONLY`, `IDEMPOTENT_WRITE`, `NON_IDEMPOTENT_WRITE`) and `workspaceRevision`.
   - Any non-`READ_ONLY` tool call that terminates with `OUTCOME_UNKNOWN` surfaces `status: 'unknown'` and `failureClassification: 'TOOL_OUTCOME_UNKNOWN'` so automatic replay is blocked until reconciled.

4. **Invariant 3 — Monetary Cost Semantics (`ACTUAL` vs. `ESTIMATED` vs. `UNKNOWN`):**
   - Local runtimes (`ollama`, `lmstudio`, `local`, etc., or `isLocalRuntime: true`) report `costStatus: 'ACTUAL'` and `costUSD: 0`.
   - Priced remote runtimes compute `costUSD` from token usage and report `costStatus: 'ESTIMATED'` (or `'ACTUAL'` when configured).
   - Unpriced remote runtimes report `costStatus: 'UNKNOWN'` and `costUSD: undefined` (never coerced to `0`).

5. **Physical Workspace Revisions, Protected Paths, Checkpoints, Cancellation & Resume:**
   - Tracks physical workspace revisions across file mutations (`fileMutations`, file hash diffs, git status changes, or custom `getWorkspaceRevision` callback).
   - Enforces `verification.protectedPaths` prior to dispatching mutating tools, recording policy denials (`policyEffect: 'deny'`).
   - Supports cooperative cancellation (`request.isCancelled`, `adapter.cancel()`, `AbortSignal`) and invokes `onCheckpoint(executionId)` on interruption, cancellation, failure, or completion.
   - Forwards `request.resumeContext` (`AgentResumeContext`) into `AgentRunRequest.resume`, preserving prior `filesChanged`, `workspaceRevision`, and execution-wide budgets while reporting net attempt token usage.
