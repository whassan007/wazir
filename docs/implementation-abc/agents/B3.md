## Implementation Summary

### 1. Shadow Routing Evaluation (`evaluateShadow`)
- Runs a proposed/candidate `RoutingPolicyDescriptor` alongside the active production policy on the exact same task and candidate pool without mutating the input candidates or altering the production routing decision (`selectedChoice` always equals `productionChoice`).
- Records both `productionChoice` and `shadowChoice` with predicted verified-success probability (`predictedSuccessProb`), expected cost (`expectedCostUSD`), expected latency (`expectedLatencyMs`), sample count, uncertainty, and predicted deltas (`successProbDelta`, `costDeltaUSD`, `latencyDeltaMs`).
- Enforces strict authorization before any live duplicate shadow run (`liveShadowExecutionAuthorized: false` unless `allowLiveShadowExecution: true`, explicitly requested, task passes privacy/locality/criticality checks, and cost fits within `perTaskMaxCostDeltaUSD` and `maxExplorationCostUSD`).

### 2. Bounded Exploration Strategy (`decideWithExploration`)
- Supports UCB-bounded (`strategy: 'ucb'`), epsilon-greedy (`strategy: 'epsilon-greedy'`), and under-sampled (`strategy: 'under-sampled'`) exploration over `(harnessId, modelId, runtimeId)` candidates whose `sampleCount < minSamplesForConfidence`.
- Enforces configurable exploration budgets:
  - `maxExplorationFraction` / `maxExplorationRate` (fraction of requests permitted to explore).
  - `maxExplorationCostUSD` / `maxExplorationCostUsd` (cumulative spend ceiling).
  - `perTaskMaxCostDeltaUSD` / `perTaskMaxCostDeltaUsd` (maximum extra per-task cost over the production choice).
- Enforces hard security, privacy, and risk constraints:
  - Never explores on `dataClassification === 'sensitive' | 'restricted'`.
  - Never explores remote/hosted candidates when `localOnly: true` or `routingMode === 'LOCAL_ONLY'`.
  - Never explores on `priority === 'critical'`, explicit `targetModelId` pins, or high-risk mutating tasks when `blockHighRiskExploration: true`.

### 3. Calibration & Rollback (`recordObservedOutcome`, `checkRollbackGuard`, `rollbackToBaseline`)
- Links physical verification outcomes (`verifiedSuccess`, `actualCostUSD`, `actualDurationMs`, `policyViolation`) to the `ShadowEvaluationRecord`.
- Computes calibration metrics: `successProbError` (`|predictedSuccessProb - (verifiedSuccess ? 1 : 0)|`), `brierScore`, signed/absolute cost estimation error, and signed/absolute latency error.
- Automatically or manually rolls back an activated candidate policy to `baselinePolicy` if a policy violation occurs, observed verified success rate drops below `minObservedVerifiedSuccessRate` (once `minRollbackSamples` are observed), or calibration error exceeds `maxCalibrationErrorThreshold`.
- Persists state and evaluation records to optional `KeyValueStore` under `shadow-router/`.
