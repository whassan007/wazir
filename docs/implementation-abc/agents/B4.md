# Agent B4 — Routing Telemetry and Explainability (`feat/router-telemetry`)

## Summary of Changes

1. **Routing Telemetry in `TelemetryCollector` (`packages/core/src/services/telemetryService.ts`)**:
   - Added `RoutingTelemetryRecord`, `RoutingTelemetryInput`, `RoutingTelemetryFilter`, `RoutingTelemetrySummary`, `RoutingCandidateAlternative`, `RoutingEligibilityExclusion`, `RoutingCalibrationEvidence`, `RoutingCacheReuseTelemetry`, and `classifyExclusionReasons`.
   - Implemented `recordRoutingTelemetry(...)`, `getRoutingTelemetry(filter?)`, and `summarizeRoutingTelemetry(recordsOrFilter?)`:
     - Tracks `executionId`, `taskId`, `jobId`, `routingPolicyVersion`, and selected `harnessId`, `modelId`, `runtimeId`, `computerId`, `workerId`, `accountId`.
     - Captures `candidateAlternatives` (with scores, predicted success probability, estimated cost, and reasons) and `eligibilityExclusions` with deterministic exclusion categories (`policy`, `resource`, `context`, `capability`, `circuit_breaker`, `availability`, `other`).
     - Tracks `predictedSuccessProbability` and `calibrationEvidence` (`sampleCount`, `confidence`, `uncertainty`, `isStale`).
     - Enforces monetary cost invariants across `estimatedCostUSD`, `actualCostUSD`, and `costStatus` (`ACTUAL` | `ESTIMATED` | `UNKNOWN` — never fabricating `$0.00` for unknown remote costs).
     - Tracks `firstTokenLatencyMs`, `endToEndLatencyMs`, `verificationDurationMs`, `coldStartOverheadMs`, `retryOverheadMs`, `retryCount`, and `cacheReuse` (`{ cacheReadTokens, cacheWriteTokens, hitRate }` when observable, or `'UNOBSERVED'`).

2. **Routing Explainability in `ExecutionExplanation` (`packages/core/src/services/executionExplanation.ts`)**:
   - Preserved all existing `ExecutionExplanation` fields and semantics so existing tests and CLI consumers pass unchanged.
   - Extended `ExecutionExplanation.routing` (and exposed `ExecutionExplanation.routingAudit`) with:
     - `harnessId`, `policyVersion`, `predictedSuccessProbability`
     - `calibration: { sampleCount, confidence, isStale } | null`
     - `candidateAlternatives` and `eligibilityExclusions`
     - `costComparison: { estimatedCostUSD, actualCostUSD, costStatus }`
     - `latencyBreakdown: { firstTokenLatencyMs, endToEndLatencyMs, verificationDurationMs, coldStartOverheadMs, retryOverheadMs }`
     - `cacheReuse: { cacheReadTokens, cacheWriteTokens, hitRate } | null`
   - Derived every field strictly from durable execution facts (`record.scheduling`, `record.events`, `record.usage`, `record.checks`, `record.execution`), emitting `null` or `[]` when data is absent and never fabricating hashes, sample counts, confidence values, or `$0` unknown remote costs.
   - Added `formatRoutingExplanationJson(explanation: ExecutionExplanation): string` for machine-readable JSON output.

3. **Unit Tests (`packages/core/tests/routerTelemetry.test.ts`)**:
   - Added 13 comprehensive unit tests covering routing telemetry collection, exclusion categorization, cost status invariants, cache reuse telemetry, summary aggregation, empirical routing explanation projection, stale calibration handling, latency breakdown derivation, absence of fabricated values, and JSON serialization.
