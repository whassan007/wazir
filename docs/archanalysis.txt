2. **What exits the loop?** Either a `done` action payload, an `answer` action payload, an `error` yield (e.g. timeout, circuit breaker), or it reaches `maxTurns`.

9. **Is the model given the tool schema every turn?** No, the system prompt containing the schema is inserted once at the top of the `messages` array.
10. **Is the model given the previous failed action?** Yes, the previous action remains in the context, and the tool error directly follows it.

# PHASE 5: TRACE ONE ACTUAL TOOL CALL (`shell`)

**Code Path:** `packages/tools/src/process-tools.ts` -> `shellTool.execute`

### What happens if command == ""?
It is blocked by the **Policy Engine** before the tool is even executed.
`packages/core/src/services/policyEngine.ts`:
```typescript
    const command = typeof request.input.command === 'string' ? request.input.command.trim() : '';
    if (!command) {
      return { decision: 'deny', rule: 'shell-unknown-ask', reasons: ['empty shell command'] };
    }
```
### What happens if command is invalid or execution returns non-zero?
`runShell` executes it, returning `ok: false` and the stderr output in `error`.
### What happens after each failure?
`fleetRunner.ts` wraps the policy denial or tool error into a `ToolResult` (with `ok: false`) and returns it to `CodingAgent`. `CodingAgent` pushes the error text into the context array, and the loop naturally continues to the next model turn.

# PHASE 11: MOST IMPORTANT QUESTION

**Conclusion A: The code explicitly permits it.**

**Here is exactly how this happens:**
1. During the agent's `implement` loop, the model repeats an invalid tool call 3 times.
2. `codingAgent.ts` (Lines 582-585) triggers `checkCircuitBreaker()`.
3. The agent yields `{ kind: 'error', error: breakerError }` and executes a `break;`.
4. **THE BUG:** This `break` exits the `while (turnsUsed < maxTurns)` loop, but execution naturally falls through into the subsequent `VERIFY (deterministic, host-side)` loop on Line 600.
5. The `VERIFY` loop runs `test`, `lint`, and `typecheck`. Since the code isn't actually broken (the model just failed to write anything), the checks pass (`failures.length === 0`).
6. `CodingAgent` blissfully yields `{ phase: 'complete' }` and `{ kind: 'done', content: 'Task completed. Verification checks passed.' }` and returns.
7. Back in `fleetRunner.ts` (Line 374), the earlier circuit breaker `error` was recorded into `engine.executions.recordError()`.
8. `evaluateExecution` (in `evaluator.ts`) checks `record.errors.length`. Because the circuit breaker logged an error, it returns `success: false`.
9. `jobOrchestrator.ts` gets `success: false`. Because "circuit breaker" is not a policy denial, the orchestrator triggers a full task retry, emitting the `task:retry` and `task:started` events.

# PHASE 14: DETERMINE ERROR PROPAGATION

1. **Empty shell command:** `fleetRunner.ts` -> `policyEngine.ts` denies execution -> returns `ok: false` -> Model context pushed.
2. **Missing write path:** `fleetRunner.ts` -> `policyEngine.ts` denies (`filesystem-outside-deny`) -> returns `ok: false` -> Model context pushed.
3. **Filesystem policy denial:** Same as above.
4. **Invalid regex:** `searchTool.execute` throws JS `SyntaxError` -> caught -> returns `ok: false, error: 'invalid regex...'` -> Model context pushed.
5. **Verification failure:** `VERIFY` runs `CHECK_TOOLS` -> `result.ok === false` -> initiates Bounded Repair Loop in `CodingAgent`.
6. **Model malformed response:** `readAction` returns `null` -> `CodingAgent` increments `correctionCount`. At 3, yields `kind: 'error'` -> breaks `WORK` loop -> falls through to `VERIFY` -> Evaluator marks `success: false` -> Orchestrator retries entire task.
7. **Model timeout:** Handled identically to malformed response (yields `error` -> breaks `WORK` loop -> falls through to `VERIFY`).

### ACTUAL ARCHITECTURE
An event-driven task DAG orchestrator wrapping an iterative conversational coding agent, separated by a rigorous intercepting policy engine and deterministic post-execution evaluator.

### CONTROL LOOPS
`JobOrchestrator` handles node dependency and task-level retries. `CodingAgent` sequentially runs an implementation `WORK` loop followed by a `VERIFY` loop (which contains its own nested bounded repair loop).

### ERROR PATHS
Execution errors (policy, shell, regex) are **non-fatal** and injected as context for the model. Agent failures (circuit breaker, timeout) break the current phase, but logic incorrectly bleeds into the verify phase before ultimately failing the evaluation check.

### RETRY PATHS
Local corrections (up to 3), circuit breaking (limit 3), verification repair cycles (default 2), and orchestrator task retries (default 3).

### TERMINAL CONDITIONS
Job orchestrator runs out of idle tasks, reaches `maxRetries`, detects deadlock, or is manually aborted via user SIGINT / task timeout controller.
