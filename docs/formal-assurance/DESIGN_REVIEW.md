## Findings requiring action

1. **High — incomplete requirement coverage (DESIGN §1.1–1.2; build §§1, 2.3–2.8, 3–5).** Architecture names later components but does not specify their operational contracts or acceptance plan. Agent 08 should land adapter parsing/probes, scheduler dispatch, repair termination/holdout, refinement provenance, durable ledger append, CLI, demo, non-goals, and phase checks before approval. See coverage table below.
2. **High — read-only fencing is conditional and bypassable (DESIGN §1.5; build §2.2).** An owning worker can restore file permissions after `chmod -R a-w`; shell policy cannot recognize arbitrary interpreter writes. Optional OS isolation therefore does not establish the claimed independent prevention layer. Require enforced read-only sandbox/container paths and fail closed when unavailable, using the existing isolation-compliance mechanism (REPO_MAP §1.3). Cover creation of absent specs directories, directory replacement, symlinks/path normalization, external harnesses, and copy-workspace fallback. Default missing/unknown roles to denied. Preserve the independent merge fence, deriving roles from trusted persisted tasks and preventing workers from selecting/escalating their own role. Test interpreter/chmod bypass and out-of-band edits, not only edit-tool denial.
3. **High — trusted dependency paths are ambiguous (DESIGN §1.2).** The layout places spec fencing helpers in assurance while policies re-exports them; assurance depends on core. Explicitly locate the authoritative role-aware fence in the existing policy implementation/facade, as requested, with no core→assurance dependency and no assurance↔policies cycle. Scheduler feasibility changes likewise belong in core Scheduler behind the existing scheduler facade. Do not create parallel policy or scheduling engines.
4. **High — same-run probes and evidence provenance are stated but not enforceable from C0 alone (DESIGN §1.3; build §§2.1, 2.7).** `VacuityProbeResult` only carries `passed/reason/details`; `VerificationResult` has no explicit run/obligation/revision identity. Specify a trusted normalization/append boundary binding probe and result to the same obligation, input hash, spec hash, and revision. Reject missing/stale probes and missing required obligations before aggregation. A raw passing verdict must not bypass this boundary by calling the release gate directly.
5. **Medium — refinement mode alone does not prove correspondence (DESIGN §1.3; build §2.6).** C0 allows a production mode and optional path but does not identify the pinned compiler, artifact/source hashes, or refinement-proof evidence. Require validated same-revision provenance before inheriting a proof; absent/mismatched provenance must yield NOT_VERIFIED. Hand translation and contract tests remain capped, with separate model/implementation records.
6. **Medium — native-outcome mismatch (DESIGN §1.3 versus C0 verdict.ts).** Design maps Scenic `sampling_exhausted` to NOT_FALSIFIED; C0 maps it to UNKNOWN. Resolve deliberately: successful completed search without violation is NOT_FALSIFIED; incomplete/failed generation is UNKNOWN (or ERROR as appropriate). Neither is a formal pass. Document exact outcome semantics and fixtures.
7. **Medium — ledger fencing needs an atomic protocol (DESIGN §1.1–1.2; build §2.7; REPO_MAP §2.2).** A hash chain plus a fencing-token parameter is insufficient. Identify the existing ExecutionEngine lease validation and durable store update used to atomically check ownership, revision and chain head before appending. Test concurrent appends, expired/stolen leases, crash recovery and tampering; do not substitute an independent JSON append for existing lease fencing.

## C0 decision

**No verdict enum changes are needed.** All required verdicts, tools, manifests, refinement modes, ledger and record shapes exist. No edits to C0 are made by this review.

Recommend additive, coordinated contract clarification before dependent implementations settle: typed run/probe/revision identity; validated refinement provenance (compiler version, hashes, proof reference); and ledger ownership identity matching existing worker/epoch/token/expiry claims. C0's optional numeric `LedgerEntry.fencingToken` is not by itself the existing execution lease's complete claim. Metadata can carry transitional fields, but the trusted boundary must require and validate them. Preserve source compatibility; do not force adapter workers to invent competing contracts.

C0 verdict.ts already blocks PROVED for Dafny trusted-base gaps (default downgrade to BOUNDED_PASS), caps formal implementation passes for contract_tests/none, rejects NOT_FALSIFIED promotion, and aggregates weakest link. These are observed code statements, not executed test results. A downgrade still requires its own passing probe. Decide/document whether gap-bearing Dafny evidence may gate as bounded evidence; the build spec explicitly requires blocking PROVED, not a blanket prohibition on every downgraded verdict.
